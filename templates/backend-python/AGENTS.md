## Structure and style
- PY-1. Layout: `src/<pkg>/api/` (FastAPI routers) → `src/<pkg>/domain/` (pure logic) → `src/<pkg>/data/` (SQLAlchemy 2.x repositories). Domain must not import `api` or `data`.
- PY-2. Full type hints; `mypy --strict` clean. No `Any` in public signatures. Pydantic v2 models for every request/response body.
- PY-3. Settings via `pydantic-settings` in `src/<pkg>/config.py`; validated at startup; no `os.environ` elsewhere.
- PY-4. Errors: raise subclasses of `AppError` (`src/<pkg>/errors.py`); an exception handler maps them to RFC 9457 problem responses. Never `except Exception: pass`; never bare `except:`.
- PY-5. Logging: `structlog` JSON with `request_id` and `trace_id`; no personal data or secrets.
- PY-6. Async all the way in request paths; no blocking I/O in `async def`. Every outbound HTTP call (httpx) has an explicit timeout.

## Data and API
- PY-7. SQLAlchemy Core/ORM with bound parameters only; no f-string SQL. Alembic migrations follow expand/contract (see root playbook); autogenerated migrations are reviewed and edited by hand.
- PY-8. The OpenAPI schema generated by FastAPI is snapshotted in `openapi.json`; `make test-contract` fails on unreviewed changes. Update the snapshot only for intended API changes.
- PY-9. Every route declares an authorisation dependency; deny by default; queries are scoped by tenant/owner.
- PY-10. Repository and migration tests use real Postgres via `testcontainers`; never mock the session.
