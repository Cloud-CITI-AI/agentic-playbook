# 4. Development standards

Each standard states the rule, the reason, and the check. "Lint" means the shared ESLint/Ruff configs; "review" means the PR checklist. Package `AGENTS.md` files carry the agent-facing subset.

## 4.1 Languages, runtimes and tooling

| Area | Standard | Why | Check |
|---|---|---|---|
| Node.js | Active LTS (24 at time of writing), pinned in `.nvmrc` and `engines` | Security support window | `engine-strict`, CI matrix |
| Package manager (JS) | pnpm ≥ 10.16 (11 preferred) with `--frozen-lockfile` | Strict dependency isolation, release-age gate, blocked lifecycle scripts | CI install step fails without lockfile |
| TypeScript | `strict: true`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` | Catches null and index errors agents commonly introduce | `tsc --noEmit` |
| Python | 3.13; uv with `uv.lock`; `mypy --strict`; Ruff | Fast, reproducible, one tool per job | `make lint typecheck` |
| Formatting | Prettier (or Biome) / Ruff format; no style debates in review | Removes noise from agent diffs | Pre-commit + CI |
| Lint | ESLint flat config incl. `typescript-eslint` strict-type-checked, `eslint-plugin-security`, `jsx-a11y`; Ruff rules `S,B,BLE,ASYNC,TRY` | Security and error-handling smells | CI, `--max-warnings=0` |

## 4.2 Project structure

| Rule | Detail | Check |
|---|---|---|
| ST-1 Monorepo layout | `apps/*` (deployables with UI), `services/*` (APIs/workers), `packages/*` (shared libs), `infra/*` (IaC) | Review |
| ST-2 Layering | `http/api → domain → data`; domain has no I/O imports | `eslint-plugin-boundaries` / `import-linter` (Python) |
| ST-3 Colocated tests | Unit/component tests beside source; integration tests `*.int.test.ts` / `tests/integration/` | Test config globs |
| ST-4 Generated code | Under `src/gen/` (or `__generated__`), never hand-edited, regenerated by a script | X10; PR size script excludes it |
| ST-5 One deployable per Dockerfile | Multi-stage, non-root user, distroless or slim base, pinned by digest | Hadolint + image scan |

## 4.3 Naming

| Item | Convention |
|---|---|
| Files (TS) | `kebab-case.ts`; React components `PascalCase.tsx` |
| Files (Py) | `snake_case.py` |
| Types/classes | `PascalCase`; interfaces not prefixed with `I` |
| Functions/vars | `camelCase` (TS), `snake_case` (Py); booleans `is/has/should` prefix |
| Env vars | `UPPER_SNAKE`, prefixed by service where shared |
| DB | `snake_case`, plural tables, `<table>_id` foreign keys, `created_at/updated_at timestamptz` |
| API paths | plural nouns, kebab-case: `/v1/purchase-orders/{id}` |
| Branches | `feat/…`, `fix/…`, `chore/…`, `agent/<issue>-<slug>`, `copilot/*` |
Check: lint naming rules where available; review otherwise.

## 4.4 Error handling (OWASP A10:2025)

| Rule | Check |
|---|---|
| EH-1 Typed error hierarchy per service (`AppError` subclasses) mapped centrally to RFC 9457 problem+json | Contract tests assert problem shape |
| EH-2 No empty catch; no catch-all without log + rethrow or explicit fallback with comment | ESLint `no-empty`, custom rule; Ruff `BLE001`, `S110` |
| EH-3 Unknown errors return 500 with generic title and request ID; never stack traces or SQL | Integration test per service |
| EH-4 Fail closed: authz or validation errors deny | Tests on deny paths |
| EH-5 Process-level handlers log and exit on unknown state; orchestrator restarts | Review + chaos test in staging |
| EH-6 Timeouts on every outbound call; retries only for idempotent ops with jittered backoff | Review; client wrapper enforces defaults |

## 4.5 Logging

| Rule | Check |
|---|---|
| LG-1 Structured JSON (pino / structlog) to stdout; one event per line | Logger factory is the only import allowed (lint) |
| LG-2 Every log has `service`, `env`, `requestId`, `traceId`, `level`, `event` | Logger middleware; contract test on one request |
| LG-3 No secrets, tokens, passwords, full bodies, or personal data (email, phone, address, gov IDs); use redaction paths | Redaction config + unit test; gitleaks on fixtures |
| LG-4 Levels: error = needs action; warn = degraded; info = business events; debug off in prod | Review |
| LG-5 Security events logged: authn success/failure, authz denial, admin actions, config changes | ASVS V16 checklist item |

## 4.6 Configuration and secrets

| Rule | Check |
|---|---|
| CF-1 Twelve-factor: config from environment, validated once at startup, typed | Startup test with missing var exits non-zero |
| CF-2 Secrets only from the cloud secret manager via workload identity; never in repo, images, CI variables in plain text, or agent context | gitleaks, push protection, image scan for secrets |
| CF-3 `.env.example` lists every variable with a fake value and a comment | Review; CI diff of `config.ts` keys vs example keys |
| CF-4 Feature flags through OpenFeature SDK; flags have owner and removal date | Flag lint job lists flags past removal date |

## 4.7 Dependency policy (OWASP A03:2025)

| Rule | Check |
|---|---|
| DP-1 New runtime dependency needs: purpose, licence (allowlist: MIT, Apache-2.0, BSD-2/3, ISC, MPL-2.0 by review), ≥ 1 maintainer active in 12 months, no known high/critical | `actions/dependency-review-action` with licence allowlist |
| DP-2 Lockfile committed; installs frozen; lifecycle scripts blocked except allowlist | CI install flags; `.npmrc` / pnpm settings |
| DP-3 Release-age gate ≥ 1 day at install; Renovate cooldown 7 days for non-security updates | pnpm `minimumReleaseAge`; `renovate.json` |
| DP-4 Prefer the standard library and existing deps over new ones | Review (A7, A8) |
| DP-5 Major upgrades require dashboard approval and a changelog read | Renovate `dependencyDashboardApproval` |

## 4.8 API design

**REST** (default)
| Rule | Check |
|---|---|
| API-1 OpenAPI 3.1 spec is the contract, committed, updated in the same PR | `test:contract` validates responses against spec |
| API-2 Versioned path (`/v1`); breaking change = new version or approved deprecation with sunset header | `oasdiff breaking` in CI |
| API-3 Errors: RFC 9457 | Contract test |
| API-4 Cursor pagination, max page size, stable sort | Review + integration test |
| API-5 Idempotency keys on POSTs that create money-moving or external side effects | Integration test with repeated key |
| API-6 Authn on every route except an explicit public allowlist; authz per handler | Route-table test asserts middleware on all routes |
| API-7 Request size limits and rate limits at the edge | Config review; ZAP baseline |

**GraphQL** (only where a BFF benefits clearly; record an ADR)
| Rule | Check |
|---|---|
| GQL-1 Schema-first, committed; breaking changes detected | `graphql-inspector diff` in CI |
| GQL-2 Depth and complexity limits; persisted queries in production | Server config test |
| GQL-3 DataLoader for N+1; field-level authz | Integration test counts queries |
| GQL-4 Introspection off in production | Config test |

## 4.9 Data access and migrations

| Rule | Check |
|---|---|
| DB-1 Parameterised queries only, via the chosen query builder/ORM | Lint (`no-restricted-syntax` on template SQL), Semgrep rule; Ruff `S608` |
| DB-2 Tenant/owner scoping in every repository read/write | Integration tests per repository (example in templates) |
| DB-3 Migrations: forward-only, expand/contract, `CREATE INDEX CONCURRENTLY`, `lock_timeout` ≤ 5s, `statement_timeout` set, no table rewrites on large tables in one step | Squawk lint in CI; PR template migration plan |
| DB-4 Backfills in batches, idempotent, resumable, run as a job not inside the migration | Review |
| DB-5 Destructive change (drop column/table) only after one release with no reads (verify via query logs) | Review; two-PR rule |
| DB-6 Least-privilege DB roles: app role cannot DDL; migration role used only by the deploy job | IaC review |

## 4.10 Frontend architecture

| Rule | Check |
|---|---|
| FA-1 Server Components by default; client boundary as low as possible | Review; bundle budget |
| FA-2 Server state via RSC fetch or TanStack Query; local state in components; no new global store without ADR | Review; dependency review |
| FA-3 Design-system components first; new primitive needs design sign-off | CODEOWNERS on `components/ui` |
| FA-4 Accessibility WCAG 2.2 AA: semantic HTML, keyboard, labels, contrast, focus | `jsx-a11y`, component axe tests, Playwright axe scan |
| FA-5 Performance budgets: LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1 (p75, Google "good" thresholds), first-load JS per route ≤ 170 KB gzip (our budget) | Lighthouse CI + `size-limit` in `perf:check`; RUM dashboard |
| FA-6 Security headers: CSP with nonces, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors` | Header test in e2e; ZAP baseline |
| FA-7 i18n-ready strings if the app is localised; no hard-coded user-facing copy in components | Lint rule (if i18n enabled) |
