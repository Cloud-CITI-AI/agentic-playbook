# 3. Agent instruction files

The production-ready files are in `templates/`. This section explains how they fit together, why they look the way they do, and how they are checked.

| File | Template | Purpose | Budget |
|---|---|---|---|
| Root `AGENTS.md` | `templates/project/AGENTS.md` | Canonical rules for every agent in the repo | ≤ 150 lines |
| Package `AGENTS.md` (frontend) | `templates/frontend/AGENTS.md` | Next.js/React additions | ≤ 80 lines |
| Package `AGENTS.md` (Node service) | `templates/backend-node/AGENTS.md` | Node/TS service additions | ≤ 80 lines |
| Package `AGENTS.md` (Python service) | `templates/backend-python/AGENTS.md` | Python service additions | ≤ 80 lines |
| `CLAUDE.md` | `templates/project/CLAUDE.md` | `@AGENTS.md` import plus Claude-only rules | ≤ 40 lines beyond the import |
| `.github/copilot-instructions.md` | `templates/project/.github/copilot-instructions.md` | Copilot code-review focus | ≤ 40 lines |
| `.github/instructions/tests.instructions.md` | same folder | Path-scoped test rules for Copilot | ≤ 40 lines |
| `.claude/settings.json` + hook | `templates/project/.claude/` | Enforcement for Claude Code (deny rules, sandbox, protected paths) | n/a |
| Cursor | none | Cursor reads `AGENTS.md` natively; add `.cursor/rules/*.mdc` only for glob-scoped rules that would otherwise bloat AGENTS.md | ≤ 40 lines each |

## 3.1 How each tool loads files (verified 2026-10-06)

| Tool | Reads | Merge behaviour | Source |
|---|---|---|---|
| Claude Code | `CLAUDE.md`/`CLAUDE.local.md` up the tree at launch, subdirectory files on demand; `AGENTS.md` only if no `CLAUDE.md` on the path (v2.1.277+), or via `@AGENTS.md` import; managed policy file; `.claude/rules/*.md` | Concatenated, root first, closest last; no override semantics | https://code.claude.com/docs/en/claude-md |
| GitHub Copilot (CLI, cloud agent, IDE) | `.github/copilot-instructions.md`, `.github/instructions/**/*.instructions.md` (`applyTo`), `AGENTS.md` (root primary, nested additional), `CLAUDE.md` | Combined; "no general precedence order" | https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-custom-instructions |
| Cursor | `.cursor/rules/*.mdc`, `AGENTS.md` (nested combined), `CLAUDE.md`, Team Rules, User Rules | Team → Project → User | https://cursor.com/docs/rules |
| Codex / others following AGENTS.md | `AGENTS.md` up the tree, nearest most specific | Concatenated | https://agents.md |

Because Copilot reads both `AGENTS.md` and `CLAUDE.md`, and our `CLAUDE.md` imports `AGENTS.md`, Copilot may see the root rules twice in some surfaces. This is a token cost, not a correctness problem (identical text cannot contradict itself). Accepted in ADR-0001.

## 3.2 Design principles (and why)

| # | Principle | Reason |
|---|---|---|
| P1 | Only facts an agent cannot discover from the code: commands, conventions that differ from defaults, constraints, prohibitions | ETH Zurich (arXiv:2602.11988): overviews and directory maps add cost without helping navigation |
| P2 | Commands first, in a table, exact and copy-pasteable | Agents follow concrete commands reliably; vague guidance ("test your changes") is unverifiable |
| P3 | Every rule has an ID, is imperative, and is checkable | Allows lessons, overrides and reviews to cite a rule; "checkable" keeps the file honest |
| P4 | Never generated by an LLM; edited only by humans via PR | Generated files measured worse than none; self-editing enables drift |
| P5 | Enforcement lives elsewhere; the file says what is enforced | Instruction files are context, not controls (Anthropic docs) |
| P6 | Package files only add or tighten | Concatenation has no precedence; contradictions make agents pick arbitrarily |

## 3.3 Precedence model

Tools concatenate rather than resolve conflicts, so precedence is a *governance* rule we enforce in review and CI, not something the tools do for us.

```
1. Org policy           managed settings, rulesets, Copilot/Cursor org policy     (enforced by platform)
2. Root AGENTS.md       repo-wide rules A*, X*                                     (CODEOWNERS: platform-eng)
3. Package AGENTS.md    FE-*, BE-*, PY-*  — may ADD or TIGHTEN only                (CODEOWNERS: platform-eng)
4. Task brief           scope, permissions for this task (e.g. "may add dependency")
5. Personal files       ~/.claude/CLAUDE.md, CLAUDE.local.md, Cursor User Rules — style only
```

Rules:
- A package file may relax a root rule only if the root rule is marked `(overridable)` and the package line cites it: `Overrides A1: diff limit 600 lines for generated SDK refreshes`. No security (`X*`) rule is overridable. No rule in v1.0.0 is marked overridable.
- A task brief can grant permissions the Never list reserves for briefs (dependencies, API contract, migrations, snapshots) and nothing else.
- Personal files must not contain rules about testing, security, git or architecture. The managed `CLAUDE.md` makes Claude-specific behaviour explicit so personal files have no reason to.
- Conflict handling for agents (root file, opening paragraph): stop and ask.

## 3.4 Size budgets and how they are checked

| Budget | Value | Check |
|---|---|---|
| Root `AGENTS.md` | ≤ 150 non-blank, non-comment lines | `scripts/check-instruction-budget.sh` in `playbook-guard` |
| Package `AGENTS.md` | ≤ 80 | same |
| Any loaded chain (file + ancestors) | ≤ 250 | same |
| `CLAUDE.md` beyond import | ≤ 40; must start with `@AGENTS.md` | same |
| Copilot instruction files | ≤ 40 each | same |
| REPO-SPECIFIC block | ≤ 30 lines | review (guidance in the block comment) |

The numbers are judgement calls anchored on Anthropic's "under 200 lines per file" guidance and the ETH finding that every line costs tokens. They are deliberately below the 200-line guidance so the whole chain fits comfortably.

## 3.5 Anti-patterns (rejected in review; some auto-detected)

| Anti-pattern | Example | Why bad | Detection |
|---|---|---|---|
| Generated file | `/init` output committed unedited | Measured to lower success, raise cost | Budget script flags "Generated by"; review |
| Directory tree / architecture essay | `├── src/` dumps | No navigation benefit; goes stale | Budget script flags tree glyphs |
| Unverifiable rule | "Write clean, maintainable code" | Agent can't act on it; reviewer can't check it | Review: every rule needs a check |
| Contradiction across files | Root: "≤ 400 lines"; package: "large PRs are fine" | Agent picks arbitrarily | Review against §3.3; overrides must cite IDs |
| Duplicated rules in many tool files | Same rules in `.cursorrules`, `CLAUDE.md`, Copilot file | Drift between copies | One canonical file (ADR-0001) |
| Secrets or internal URLs | Staging tokens in examples | Leak via context and logs | gitleaks; review |
| Personality prompts | "You are a 10x engineer" | Tokens with no measurable effect | Review |
| Rules agents cannot follow | "Get design approval before coding" in an async cloud agent | Agent will skip or stall | Convert to a gate (CI, ruleset, plan-approval label) |
| Self-edited rules | Agent "updates AGENTS.md with learnings" | Drift; prompt-injection persistence (ASI06) | Hook + guard + CODEOWNERS |

## 3.6 Variant matrix

| Concern | Root | Frontend | Node service | Python service |
|---|---|---|---|---|
| Commands | install/verify/format; standard script names | dev, unit, e2e, snapshots, mutation, perf | unit, integration, contract, migration, codegen | uv, make targets, alembic |

## 3.7 Changing an instruction file

Only by a human PR to the playbook repo (or inside a REPO-SPECIFIC block, by a human PR to the project repo), following `docs/10-self-regulation.md` §10.3. Agents write their suggestion into the PR description's "Rule proposal" section.
